### Runtime isolation blocker

A temporary `KRONOS_HOME` alone does not isolate a packaged launch:

- Production `DaemonHandle::start_network` opens canonical `\\.\pipe\kronos-ipc` on Windows; the port-specific/cfg(test) route is not the packaged startup route.
- `main.rs` installs the single-instance plugin and calls `deep_link().register_all()` during setup. A second launch can interact with the existing instance or OS scheme registrations.
- Shared-memory names in `kernel/server.rs` and `kernel/shm.rs` are fixed, not derived from the temporary home. Windows mappings can open existing objects.

No packaged process was launched to test whether those collisions occur. These are source-confirmed isolation hazards, not reproduction of the user's disconnect. Actual GUI tests need an isolated Windows environment or an approved namespace/side-effect isolation amendment before launch. User approved the [isolation design](../specs/2026-11-17-desktop-local-ipc-design.md#pending-amendment-isolated-native-acceptance); [implementation plan](2026-11-18-desktop-ipc-acceptance-isolation.md) subsequently approved by user's next `yes`. Isolation execution started; GUI launch remains gated behind complete namespace/side-effect coverage and owned supervision. New-plan receipts live in `.superpowers/sdd/2026-11-18-desktop-ipc-acceptance-isolation/`; original Task 6 remains blocked/not default.

Original corrected native runs (logs 14–15) use one owned temporary process home via both `KRONOS_HOME` and `PASEO_HOME`, plus existing fixture-owned temporary admission credentials. Homes are removed after their owned test exits. Only those test processes/listeners were started/stopped; no installed desktop or production daemon was launched/contacted.

Follow-up makes the new peer-drop test self-isolating: parent creates a temporary home, invokes only its exact test in an owned child with `Command.env` and a deterministic child marker, and never initializes daemon globals. Before daemon initialization, child asserts both homes equal its marked temporary directory and `get_data_dir()` resolves there; parent asserts inherited home variables unchanged and removes only owned directory after child exit. Log 29 verifies those assertions with **no caller-home overrides**, one passing exact test in child and one passing parent wrapper; log 30 confirms no cargo/rustc/linker remains. No shared-process environment mutation, cache cleanup, production code/config change, or unknown default-home inspection occurred. Original isolation lapse below remains disclosed.

Scoped review fix adds in-test deadlines: parent waits at most 15 seconds normally (5 seconds for controlled stall), then terminates only its owned child and waits up to 3 seconds for confirmed exit before home cleanup; if exit cannot be confirmed, owned home is preserved with failure diagnostics. Child WebSocket connect/upgrade is bounded to 3 seconds and complete workload to 10 seconds.
